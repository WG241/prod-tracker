The current policy now requires an unfrozen tracker, and the historical policy retains its recorded scope checks. The policy regression now explicitly denies frozen tasks through the current path.

4. `server/index.ts:47`, the production document fallback originally replaced the navigation guard's `no-store` header. It now preserves an existing cache policy. The final followup also inspected `server/auth/router.ts`, which keeps that policy when downstream Vite HTML handling attempts to replace it.
5. `tests/auth/integration.test.ts:164`, the email mismatch assertion originally reused a session revoked earlier in the same test. It now signs in again before introducing the mismatch and asserts both denial and removal of that fresh session.
6. `server/auth/service.ts:57`, clearing the email throttle originally happened in the router after the completed audit had been written. 7. `server/auth/router.ts:125`, downstream Vite serving could originally replace the navigation guard's 503 with 200 during a database outage. The failure branch now preserves 503 at the final response write while serving the neutral retry document. The outage regression deliberately uses a downstream fallback that attempts both 200 and `no-cache`, then asserts 503 and `no-store`.
